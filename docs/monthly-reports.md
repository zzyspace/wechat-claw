# 门店月度项目报表

## 入口与权限

- 页面：`/expense/monthly`；入口位于 `/expense` 的“新建报账”旁。
- 统一账号管理 → 报账后台 → 勾选“查看月度报表”（`report:monthly:view`），依赖“查看”（`report:view`）。既有账号不会自动获得该权限。
- 页面、静态资源、选项、汇总、明细和 CSV 导出均在服务端检查这两项权限；前端默认隐藏入口，只有明确返回 `canMonthlyReport: true` 才显示。
- 使用已有 `viewScope` 的门店、渠道、本人归属范围。在 SQL 查询时先限制账号/渠道，再汇总；不以报账人文字判定账号归属。
- 有权限但查看范围不完整时，页面提示“仅包含当前账号有权查看的记录”。“店长报账显示张志延”不改写数据库，也不扩大张志延账号的访问范围。
- 附件仍单独要求 `attachment:view`，通过原附件接口读取；无附件权限时，详情不返回缩略图元数据。
- 旧版 Basic Auth 模式继续沿用管理员角色拥有管理功能的兼容规则，合伙人/店长无月报权限。统一权限模式只检查显式授权，不从角色推定。

## 月份和归类

月份采用后台已有的创建时间归月口径，按应用时区（通常为 Asia/Shanghai）计算月初到下月月初的半开区间。与现有后台创建日期筛选及备注“某月账”的归月逻辑一致，不按凭证日期筛选。

规则定义在 `src/scenarios/reimbursement/monthly-report.ts`：

1. 快驴
2. 澳美佳 / 安之乐 / 知其味，任意字样命中均合并
3. 墨赞
4. 其他食材，未命中指定项目的食材兜底
5. 店长报账（仅来源渠道为三家门店的店长报账群，不依据 OCR、备注或类别识别），统一展示为张志延
6. 房租
7. 宿舍房租
8. 水电
9. 工资
10. 花卉，仅依据 flower 类别，店长报账来源优先，其后花卉类别优先于字样匹配
11. 其他，不属于以上项目的剩余记录

店长报账仅依据存储的渠道代码 reimbursement_fuzzy_manager、reimbursement_peanut_manager、reimbursement_fuzzy_qz_manager 判断，最高优先级合并渠道内全部记录。非店长渠道的 flower 类别统一归入花卉，不以 OCR/备注识别花卉。其他指定项目匹配 OCR 或备注，宿舍房租避免误入房租；其他冲突按项目顺序选择第一个。未命中指定项目时，rent、utilities、salary 类别分别归入房租、水电、工资，food 归入其他食材，剩余记录列为其他。报账人优先按张志延、李晨晨、邓振国排列，其他姓名随后；每人名下再按项目顺序排列。每笔仅归入一个组。

汇总键为报账人 + 项目 + 币种，类别保留标签但不拆组。不同币种不相加，界面可切换币种。有效金额用整数分累加；缺失、非有限、超出单笔安全精度或币种缺失的记录单独计数。总额超过安全整数精度时拒绝返回不准确的金额。

## 接口

所有接口位于 `/expense/api/monthly-reports`，均只读、禁止缓存，并在每次请求时重新验证账号权限。

- `GET /options`：允许门店、项目规则、固定报账人顺序、当前月份、附件能力。
- `GET /?month=YYYY-MM&store=fuzzy`：整月汇总。读取完整月度记录，不受普通列表 1000 条分页上限影响。
- `GET /details?month=...&store=...&projectId=...&reporter=...&currency=...&offset=0&limit=50`：五列详情，最多每页 100 条，保留原始姓名。只返回创建时间、报账人、类别、备注、附件预览元数据和内部定位 ID；不返回 OCR、账号标识或文件路径。
- `GET /export?month=...&store=...&currency=...&reporter=...&q=...`：按照相同排序和筛选导出 CSV。用户文本进行公式注入转义，负数金额仍保留数值格式。

页面为同源原生 HTML/CSS/JS，无 React/CDN 或内联脚本依赖，独立 CSP 已在真实浏览器下核验。附件缩略图沿用报账后台的主图片；预览支持已加载条目间切换。

## 验证和交付范围

- wechat-claw：`npm test`；新增规则、时区边界、币种/金额、CSV、权限撤销、跨门店/本人隔离、1000+ 条完整汇总与详情分页测试。
- admin-auth-gateway：`npm test`；新增独立授权及查看权限依赖校验。
- server-infra：`npm test`；新增受保护页面与资源路由校验。
- 浏览器使用临时数据库及模拟网关验证实际页面：入口位置/隐藏、项目排序、分页、附件、币种、XSS 转义、手机与深浅色布局。

上线需协调三个仓库：先发布报账服务以识别新权限，再发布账号管理以配置授权，server-infra 发布 `/expense/monthly` 及 `/expense/monthly/` 的受保护路由。新索引 `idx_reimbursement_reports_channel_created_at` 在数据库迁移时幂等创建；不改写账目。

部署不会自动授予生产账号新权限；需在统一账号管理中按需勾选“查看月度报表”。发布只需重启报账后台与账号网关，由 server-infra 校验并重载路由，保留机器人和其他业务服务状态。
