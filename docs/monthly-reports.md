# 门店月度项目报表

## 入口与权限

- 页面：`/expense/monthly`；入口位于 `/expense` 的“新建报账”旁。
- 统一账号管理 → 报账后台 → 勾选“查看月度报表”（`report:monthly:view`），依赖“查看”（`report:view`）。既有账号不会自动获得该权限。
- 页面、静态资源、选项、汇总、明细和 CSV 导出均在服务端检查这两项权限；前端默认隐藏入口，只有明确返回 `canMonthlyReport: true` 才显示。
- 使用已有 `viewScope` 的门店、渠道、本人归属范围。在 SQL 查询时先限制账号/渠道，再汇总；不以报账人文字判定账号归属。
- 有权限但查看范围不完整时，页面提示“仅包含当前账号有权查看的记录”。“店长报账显示张志延”不改写数据库，也不扩大张志延账号的访问范围。
- 附件仍单独要求 `attachment:view`，通过原附件接口读取；无附件权限时，详情不返回缩略图元数据。
- 旧版 Basic Auth 模式继续沿用管理员角色拥有管理功能的兼容规则，合伙人/店长无月报权限。统一权限模式只检查显式授权，不从角色推定。

## 月份和归类

可选月份从 `2026-09` 起，`2026-08` 及更早月份禁止选择或查询。进入页面默认选中应用时区下的上一个月；若上一个月早于可选范围，则使用 `2026-09`。合法链接中明确指定的月份仍按链接选择；早于范围或格式无效的链接月份回到默认月份。日期选择器、上个月按钮，以及汇总、明细、CSV 接口使用相同下限。

月份采用后台已有的创建时间归月口径，按应用时区（通常为 Asia/Shanghai）计算月初到下月月初的半开区间。与现有后台创建日期筛选及备注“某月账”的归月逻辑一致，不按凭证日期筛选。

新增月账备注支持 `x月账`、`YYYY年x月账`，以及“月帐”写法。明确年份直接采用；省略年份时，目标月份不晚于参考月份取当年，晚于参考月份取上一年。创建时间设为该月最后一天 `23:59:59`，按应用时区计算。后台编辑以本次操作时间为参考，新建与补录以消息接收时间或填写的报账时间为参考。新追加的标记覆盖旧归属；追加普通备注、补图不会重算旧标记，历史记录不批量重算。

规则定义在 `src/scenarios/reimbursement/monthly-report.ts`：

1. 快驴
2. 金辉，OCR 或备注包含「金辉」；OCR 同时包含其他项目关键词时，其他项目优先，展示位置不变
3. 澳美佳 / 安之乐 / 知其味，OCR 或备注包含澳美佳、安之乐、知其味、恰沐阳任意字样均合并到此项目，项目名称保持不变
4. 景洲，OCR 或备注包含「景洲」
5. 墨赞
6. 其他食材，未命中指定项目的食材兜底
7. 店长报账（仅来源渠道为三家门店的店长报账群，不依据 OCR、备注或类别识别），统一展示为张志延
8. 房租
9. 宿舍房租
10. 水电
11. 工资，仅依据 salary 类别，不匹配 OCR 或备注；店长报账来源优先，其后工资类别优先于字样匹配
12. 花卉，仅依据 flower 类别，店长报账来源优先，其后花卉类别优先于字样匹配
13. 其他，不属于以上项目的剩余记录

店长报账仅依据存储的渠道代码 reimbursement_fuzzy_manager、reimbursement_peanut_manager、reimbursement_fuzzy_qz_manager 判断，最高优先级合并渠道内全部记录。非店长渠道的 salary、flower 类别分别统一归入工资、花卉，不以 OCR/备注识别工资或花卉。其他指定项目匹配 OCR 或备注，宿舍房租避免误入房租；其他冲突按项目顺序选择第一个。未命中指定项目时，rent、utilities 类别分别归入房租、水电，food 归入其他食材，剩余记录列为其他。报账人优先按张志延、李晨晨、邓振国排列，其他姓名随后；每人名下再按项目顺序排列。每笔仅归入一个组。

汇总键为报账人 + 项目 + 币种，类别保留标签但不拆组。不同币种不相加，界面可切换币种。有效金额用整数分累加；缺失、非有限、超出单笔安全精度或币种缺失的记录单独计数。总额超过安全整数精度时拒绝返回不准确的金额。

OCR 同时包含「金辉」和任意其他项目关键词时，跳过金辉匹配，其他项目仍按原顺序决定归类。例如「金辉餐料」与「上海恰沐阳国际贸易有限公司」同时出现，归入澳美佳 / 安之乐 / 知其味；「金辉」与「宿舍房租」同时出现，归入宿舍房租。仅备注同时出现多个关键词，或 OCR 仅包含金辉、其他关键词仅在备注中时，沿用原有匹配顺序。「工资」不再属于项目关键词，不参与金辉 OCR 冲突判断。店长来源优先，其后工资、花卉按类别直接归类。

## 接口

所有接口位于 `/expense/api/monthly-reports`，均只读、禁止缓存，并在每次请求时重新验证账号权限。

- `GET /options`：允许门店、项目规则、固定报账人顺序、当前月份、默认月份、最早可选月份、附件能力。
- `GET /?month=YYYY-MM&store=fuzzy`：整月汇总。读取完整月度记录，不受普通列表 1000 条分页上限影响。
- `GET /details?month=...&store=...&projectId=...&reporter=...&currency=...&offset=0&limit=50`：六列详情，最多每页 100 条，保留原始姓名。只返回创建时间、报账人、类别、备注、附件预览元数据、金额、币种和内部定位 ID；不返回 OCR、账号标识或文件路径。
- `GET /export?month=...&store=...&currency=...&reporter=...&q=...`：按照相同排序和筛选导出 CSV。用户文本进行公式注入转义，负数金额仍保留数值格式。

页面为同源原生 HTML/CSS/JS，无 React/CDN 或内联脚本依赖，独立 CSP 已在真实浏览器下核验。附件缩略图沿用报账后台的主图片；预览支持已加载条目间切换。

## 验证和交付范围

- wechat-claw：`npm test`；新增规则、时区边界、币种/金额、CSV、权限撤销、跨门店/本人隔离、1000+ 条完整汇总与详情分页测试。
- admin-auth-gateway：`npm test`；新增独立授权及查看权限依赖校验。
- server-infra：`npm test`；新增受保护页面与资源路由校验。
- 浏览器使用临时数据库及模拟网关验证实际页面：入口位置/隐藏、项目排序、分页、附件、币种、XSS 转义、手机与深浅色布局。

上线需协调三个仓库：先发布报账服务以识别新权限，再发布账号管理以配置授权，server-infra 发布 `/expense/monthly` 及 `/expense/monthly/` 的受保护路由。新索引 `idx_reimbursement_reports_channel_created_at` 在数据库迁移时幂等创建；不改写账目。

部署不会自动授予生产账号新权限；需在统一账号管理中按需勾选“查看月度报表”。发布只需重启报账后台与账号网关，由 server-infra 校验并重载路由，保留机器人和其他业务服务状态。

手机端报表详情采用与报账后台一致的纵向条目：报账人、类别、金额置顶，备注与可直接点击放大的附件缩略图并排，创建时间置底，无需横向滚动。桌面保留六列表格；两种布局复用相同分页数据和附件权限。

交互：月报汇总行整体可点击打开项目明细；明细条目在月报内打开后台同款原始详情弹窗，不跳转页面。构建时直接复用 admin.html 的详情渲染模板与样式，既有详情接口校验权限；有编辑权限时可在弹窗内编辑，关闭后刷新月报。附件缩略图只打开附件预览，不触发跳转。

报账详情（后台和月报内共用）增加“删除记录”按钮，须同时满足账号删除能力与详情接口返回的 `permissions.canDelete === true`。支持删除本人上传权限，但仍依据存储的账号归属及查看范围判定；确认后调用现有 DELETE 接口。月报内删除成功后关闭原始详情并刷新当前项目明细与汇总。
